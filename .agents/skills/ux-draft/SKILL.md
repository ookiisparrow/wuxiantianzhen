# 轻量草稿提案工作流 (`ux-draft`)

本技能用于项目探索期的**快速设计提案**。把注意力集中在**界面结构提案、交互走查完整性与设计规范一致性**上，砍掉精修阶段的重型测试开销。

## 1. 适用边界（双轨制分工）

| 维度 | 草稿提案模式（`ux-draft` · **默认**） | 精修定稿模式（全链路流水线 · **按需点名**） |
|---|---|---|
| **触发场景** | 新增/改版 `design/*.html`、探索新功能界面、对比布局方案 | 用户明确要求「精修 / 定稿」，或将方案合入 `packages/mp-*`、`packages/admin` |
| **加载技能** | 仅读本文件（需多方案切换时最多加读 `prototype` 或 `variant`） | 串联 `weaver-ux-guard` + `mobile-native` + `gestures` + `emil-design-eng` + `choreograph` + `better-ui` + `better-accessibility` + `break-ui` |
| **交付重心** | **设计提案说服力 + 100% 页面与状态界面完整可点** | 像素级同心圆角、焦点陷阱、多指手势容错、极限长文本抗压 |
| **验证深度** | 毫秒级静态 Token 自检（`< 50ms`），免无头浏览器矩阵与 `npm test` | `check-weaver-ux.mjs --browser` 双视口实测 + `break-ui` 矩阵 + 截图取证 |

## 2. 必须保留的设计规范底座（直接复用，免二次查阅）

草稿虽轻，视觉与交互红线不降级。新建 `design/*.html` 时直接沿用以下基准 Token：

1. **已采纳全局视觉风格（质检靛青灰 `slate_indigo` · 全端沿用）**：
   - 背景 `--bg: #F5F6F8` · 卡片 `--card: #FFFFFF` · 弱底 `--soft: #EEF0F4`
   - 品牌主色 `--brand: #293B63`（深态 `#1D2B4A`、浅底 `#F0F3F9`）
   - 语义色：合格 `#177245` / 警示 `#945610` / 错误 `#C43626`
   - 文字层级：`rgba(17, 24, 39, 0.92)` / `0.64` / `0.46`
   - 后续草稿直接沿用该定版色板，无需再附带多套配色切换器。
2. **微信 WeUI 原生字阶（严禁随意字号与手机端 Emoji）**：
   - 看板数字 `34px`（`tabular-nums`）· 页面大标题 `22px` · 导航/主按钮/选项主文 `17px` · 次要正文 `15px` · 辅助说明 `14px` · 次级标签 `12px`；字重克制在 `400–600`，`<input>` 字号固定 `17px`。
3. **分端核心纪律**：
   - **织女端（`design/*weaver*`）**：死守 `AGENTS.md` §5 与 `.agents/rules/design-copy-rules.md`——**一屏一画面禁纵向滚动、一页一重点、点选直进且左上角全程可返回**，以及**文案五条铁律**：① 内部用语改通用语言；② 措辞小学生也能懂（无生僻字与英文单位）；③ 参考微信/抖音/淘宝成熟通用语；④ 四不出现（不应看到、无意义、会迷惑、不能指导行动一律删）；⑤ **零同屏重复、零废话填充**（同屏同一意思只说一次，图示/直白选项不硬凑副说明，考核题不写剧透副标题）。
   - **买家与志愿者端（`design/*buyer*` / `*volunteer*`）**：突出手作实拍质感、工期与退换规则透明、盲审 8 秒读秒清晰。
   - **运营总控台（`design/*admin*`）**：桌面高密度工作区、状态流转徽章清晰、批量导入导出动线直达。
4. **零成本默认手感**：
   - 动效统一用 `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`，时长 `120ms–220ms`（禁 `ease-in` 与 `scale(0)`）；`:hover` 放入 `@media (hover: hover)`；可点控件最小高度 `>= 44px`（主按钮 `48px`）；附带一行 `@media (prefers-reduced-motion: reduce)` 兜底。

## 3. 三步极速执行流

### Step 1 · 先亮设计提案（1 句话定位 + 轴向拆分）
- 动笔前先明确本稿的核心设计主张（布局如何划分、信息如何减负、关键状态如何流转）。
- 若需给用户提供多方案比选，在同一 HTML 右侧放轻量切换栏，在 **布局结构 / 信息密度 / 引导方式** 轴向上给出 2–3 个真正不同的提案，不拿纯换色充当变体。

### Step 2 · 单文件全界面完整交付（UI Completeness First）
- 输出单文件自包含 HTML（内联 CSS + 真实业务文案模拟数据 + SVG 简洁线框/图示，禁 Lorem Ipsum）。
- **界面必须完整闭环**：主流程每一屏、分支状态（空态、待审、通过、驳回、底部抽屉/弹窗）全部画出并可点击切换；右侧附带 **页面速览跳页目录**，方便评审者一秒直达任意状态，严禁出现「此处略」占位块。

### Step 3 · 毫秒级静态自检即交付
- 若为织女端草稿，仅跑毫秒级静态规范检查（**不加 `--browser`**）：
  ```bash
  node .agents/skills/weaver-ux-guard/scripts/check-weaver-ux.mjs design/<target>.html
  ```
- 向用户交付文件链接、核心设计决策取舍表（`方案亮点 / 取舍代价`）及待拍板问题，**立即停手等待反馈**。

## 4. 草稿阶段减负红线（严禁过度工程）

在用户拍板定稿前，**明确跳过**以下动作以换取最快迭代速度：
- 不读取 `break-ui`、`better-accessibility`、`choreograph`、`gestures`、`mobile-native`、`better-ui` 等精修审计技能；
- 不编写极限超长乡镇名/地址压力测试集（`worst-case fixtures`）；
- 不启动无头浏览器跑 `375×667` × `320×620` 多视口排列组合脚本；
- 未改动 `packages/*` 或 `scripts/*` 代码时，不运行 `npm test` 与 `verify-wxtz`。
