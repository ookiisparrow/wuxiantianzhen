# 无限天真 · 界面与文案设计规则

本文件为项目级设计规则，凡编写或修改 `design/*` 原型与 `packages/mp-weaver`、`packages/mp-buyer` 界面文案及交互时必须遵守。

## 一、文案五条铁律（强制执行）

1. **内部用语一律改为通用语言**
   - 严禁向用户暴露业务、运营、财务、风控或开发内部术语。
   - 禁用示例：`织女入驻`、`派单`、`正式开单`、`收线地址`、`周转保证金`、`防损专户`、`质检组`、`起步毛线`、`织女库`、`已入档`、`排期评估`、`在途订单`、`防盗图`、`拉起`、`自动绑定`。
   - 替换示例：`报名接单`、`进度通知`、`开始接单`、`收货地址`、`押金`、`无限天真收件处`、`12 团毛线`、`手里的单`。

2. **所有文案措辞必须使小学生也能理解**
   - 优先选用少笔画、日常高频口语词，句子压到最短。
   - 禁用生僻字（如 `茜`、`挺括`）、书面语（如 `充棉圆润度`、`五官端正`、`色彩柔和度`）与英文缩写单位（用 `6 厘米`，不用 `6cm`）。
   - 色卡、动作与结果用直观日常词（如 `大红`、`米黄`、`浅蓝`、`圆圆鼓鼓的`、`扁扁的、发皱`、`两边一样大`）。

3. **参考微信、抖音、淘宝成熟通用用语**
   - 高频入口、按钮、状态名直接沿用国民级 App 的成熟表达，零学习成本：
     - 登录与资料：`微信一键登录`、`使用微信手机号`、`选择微信收货地址`、`收货地址`
     - 快递与扫码：`预约上门取件`、`选择取件地址`、`立即预约`、`一键复制收件地址`、`扫一扫`
     - 消息与支付：`开启消息提醒`、`查看进度`、`微信支付`、`确认支付`、`原路退回`

4. **「四不出现」过滤原则**
   - 如果一段文案满足以下任意一条，则**绝不应该出现**：
     1. **不应该被织女看到**（后台评分、静默分流、名额池、风控核验意图、内部流程机制）；
     2. **织女看到后没有意义**（自夸式说明、解释已被取消的功能如「免拍身份证」「无需写纸条」、无法指导行动的后台编号展示）；
     3. **织女看到后会产生迷惑**（未经询问却主动提「全国各地不设门槛」「仓库扫码直认」等令人起疑的表述）；
     4. **织女看到后不能指导她的具体行动**（重复预告「点选后自动进入下一页 · 点左上角可返回」等废话提示）。

5. **零同屏重复，零废话填充（能不写就不写）**
   - **同一屏同一层意思只说一次**：大标题说清的，副标题和列表卡片严禁换句话重说一遍（如标题已写「开始接单前要交 200 元押金」「作品已收到」，下方不得重复写「开始接单前再交 200 元」「3 张照片已收好」）。
   - **图示与控件能看懂的绝不配多余字**：左右并排选图直接点图（不配「选左边/选右边」）、正误对比图带勾叉（不在图下重复上方说明文字）、按钮自带动词（右侧只留箭头 `›`，不重复「去选择」）。
   - **选项本身直白时不强行凑副标题**：如「接过单 / 没接过单」「每天 1–2 小时 / 3–4 小时 / 半天以上」单行即可，严禁为了撑版面硬写同义解释；考核题（如审美 10 题）严禁写多余副标题避免干扰或提前剧透答案。

6. **筛选题零正负面暗示（防迎合伪装）**
   - 凡用于评估态度、习惯、品控或风控的筛选题，题干与选项**严禁出现明显的褒贬词或“标准答案感”**（如「愿意改好 vs 不太想拆」「马上沟通 vs 拖着不管」「必须看视频」「不太方便」），避免织女一眼看穿意图而迎合选好话。
   - 一律改写为**中性事实题、日常场景分享题或体面两难偏好题**（每个选项听起来都合理自然、没有对错感），让织女放松如实作答，后台再按暗标分池；易被伪装的风险项（如烟味）不靠口头提问，交给实物寄样验收核实。

## 二、织女端交互与视觉定版规则

1. **配色基准**：统一沿用已采纳的 **质检靛青灰**（`--brand: #293B63` / `--bg: #F5F6F8` / `--card: #FFFFFF`）；调用微信原生能力（登录、手机号、定位、地址簿、相机/相册、扫一扫、订阅消息、微信支付）时严格采用微信原生组件样式与官方绿 `#07C160`。
2. **字号基准**：遵循微信 WeUI 官方字阶（`34 / 22 / 17 / 15 / 14 / 12px`，字重 `400–600`，零 Emoji）。
3. **布局与操作**：一屏一画面禁止纵向滚动；一页一重点；首页一次性完成微信原生采集；选择题与拍照项点选即自动进入下一屏，非首页左上角全程保留「返回」按钮；不设「听一遍」语音按钮。
4. **自动化门禁**：每次新增或改动织女端页面，必须执行 `node .agents/skills/weaver-ux-guard/scripts/check-weaver-ux.mjs <target>` 且 `0` 告警通过。
