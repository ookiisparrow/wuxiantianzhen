## 3. 买家端规则（取消、退货、定金等）

## 4. 订单、合单与派单

**[11-14] 业务需求 v1**
- 订单单位是**顾客的订单包**，整包只给一位织女，一个包裹一个码。`已定`
- 优先分配制，不抢单；每天 **9:00 到 13:00 每个整点派单**，最晚 14:00 结束；每位织女每次最多 3 单、1 小时内回复，可一单都不接（不扣分，记回复率）；当天没分出去的，次日 9:00 再派；同一订单最多依次推给 5 位织女。`已定`
- 候选筛选：先排除（开关关闭/休息日、容量满、色号不全、预计邮费超上限），再按层级（有现成品、回头客、同省、同大区、全国），同层订单少时机会均等，订单多时叠加信用分。
- 拒绝、超时不扣信用分，但记回复率；连续 3 次超时暂停派单 7 天；被买家取消和超期比例超阈值暂停派单。
- 没人接：5 位用完放宽层级，次日再取 5 位；仍无人或超 24 小时进待处理，由运营联系买家（建议）。

## 5. 织女端流程

**[11-14] 业务需求 v1（线性工作流，已定）**
接受并核对材料（接单即开工）→ 订单包轮到队首时放出图解 → 做完后**扫包装袋上的随机二维码绑定这一包** → 现场拍产品照（拍到包装袋二维码）→ 照片审核放行 → 装袋贴封签再拍 → 才出现寄送按钮 → 约取件 → 下一包成为队首。
- 接单核对材料（建议）：1 小时内扫完所需色号线团条码才算接单成功，超时/扫不出推给下一位。
- 图解仅队首可看，带织女工号水印，订单结束后链接失效；没有授权记录的款不能上架。
- 买家地址不可见：织女只看到收件省市用于估邮费；约取件时由系统把地址交给快递聚合平台。
- **随机二维码包装袋**：平台预先印好带唯一随机码的袋子**寄给织女备用**，状态：未发出、已发出、已绑定、已寄出；袋子用完可申请补袋，成本由运营费承担。
- 收入页、接单开关（可随时关，不扣分）、通知（每天 8:50 提醒"今日 9:00 开始派单"，整点有新单小程序内提醒为主、短信为辅）。
- 寄出前照片审核：种子阶段运营看；评委库建好后，2 位志愿者都通过才放行，有人不通过或 4 小时没人看转运营。
- 织女自己去寄：**取消**；快递没来就重新约取件。

**[11-21] HANDOFF**：织女端最后一步统一：**装袋贴封签拍照 → 选择方便上门的取件时段 → 点提交发货**；完工后使用**通用半透明八边封袋 + 平台定做的唯一二维码贴纸 + 一次性防拆封签**；先拍成品照送审（一期运营审、二期 2 位志愿评委瀑布流投票）；织女与买家全程信息隔离。

**[11-22]**
- 取件时段：**仅作提示，不保证**（抖店在线寄件未确认可指定时段）。
- **袋码**（贴纸二维码）= 订单包级，一包一码，不绑实物；平台**批量寄给织女，用完后在小程序申领**；每张状态 `unused → bound → void`（集合 `bagStickers`）；余货被新订单复用时旧贴纸作废、换新贴纸并重拍封签照；低于阈值提示申领。
- 术语：**款号**（`skuCode`，抖店商家编码，款级）与**袋码**（`bagQrCode`）分开；不使用"件码"。

✅ 当前有效：以 [11-22] 为准。

## 15. 抖店侧调研结论汇总（均为官方文档只读调研，11-14 至 11-18）

> 来源标注：「文档明确」「文档没写」「推断」。AI 客服（抖店开放平台智能客服、学习中心 AI、快递100 "果宝"）的回答只能视为参考。

### 15.1 规则类
- **预售发货期**（11-14，D1）：预售时效目前最长 15 天，特殊类目另行评估；>15 天有独立超时判罚档；发货超时赔付按订单实付 1%/5%（最低 2–5 元，最高 50 元）；超时 120 小时仍未发货可能按 10% 扣违约金（2023 旧稿，现行待核）；揽收：发货后 24 小时内无第一条物流揽件即揽收超时。→ 14 天交期在上限内，但要计入 24 小时揽收。
- **定制商品与退款**（D2）：定制类不执行"未发货极速退款"，一般不支持七天无理由；开始加工后无理由退款应与商家协商，损失由消费者承担但**商家需举证**；不得约定过分高于实际损失的违约金。→ **20% 固定定金归织女在抖店订单上没有文档依据**；"手工钩织预售商品"是否算定制取决于是否有买家指定的个性化信息（推断）。抖店自带"定金预售"里，定金不退只覆盖"尾款到期未付"。
- **收件人解密**（D3、5.1–5.3）：解密接口收费；明文不得落库；解密率不高于 5%（2021 旧规，待核）；每日额度；订单状态限制（待支付、已关闭等不得解密）；**调用解密接口的系统须部署在抖店云内**（2023-08-31 起）；不调用解密接口、只用密文取号则不用入云（机器人答，待核）。
- **官方面单 vs 自行寄件**（D4、D5、§8、§11、§28、§32）：自行寄件有每日动态额度，不可查、不可提额，直播订单与普通订单共享；校验运单收件人信息与订单一致、首条轨迹早于支付时间则无法发货；多条提示要求使用官方电子面单；虚假发货规则把"非平台合作物流公司""线下发货"列为可能被判的场景。
- **个体户**（D9）：个体工商户可入驻，类目要在营业执照范围内；手作/非遗类目保证金与技术服务费原表未读。
- **订单与直播场次字段**（11-15）：`room_id`（仅直播间订单）、`author_id`、`video_id`、`c_biz`；每次开播新 `room_id`，需运营归并为一场；`searchList` 入参没有 `room_id`。
- **自用型应用**（D8）：面向商家，可授权多个店铺，可用 API 与消息推送；一个店铺只能授权给一个自用型应用；仅限同一主体。

### 15.2 在线寄件（抖店原生，用户最终采用）
- 入口、物流商、价格、17 点规则、流程、结算：见 §14。要点：**无需付给快递员**；0–30 kg；可保价 ≤5 万；2 小时无人接单可重新寄件；揽收前可取消并当日退运费。
- **限制（11-18 官方 AI 摘要+原文）**：只支持**本店铺订单和售后单**，不能手填收件人，不能不关联订单寄件；开通城市有名单，发货城市不在名单则无法使用；寄件方式含自选快递上门、上门取件、快递柜、驿站、自行寄回。
- **API 暂停**：官方常见问题（2026-06-29）"API 方案已暂停，不支持新增对接"；智能客服答复无任何申请途径；开放平台目录无对应接口。
- **发货地址库**：一家店铺最多 500 个地址（官方 FAQ 2024-08-09）；创建频率 1 秒 1 次；地址库唯一；在线寄件是否同库——推断同库。个人住宅能否作发货地址 / 面单谁提供 / 批量按订单号筛选：智能客服答"不知道"，已写成工单（见 §17）。
- **已对接在线寄件的 ERP**：我打打单、店管家、快递助手、发货易、网上管家婆、灵通打单（流程里仍有"打印快递单"）。服务市场里有**两个"快递管家"**：service_id=10 是快递100 的（PC 软件，支持订单导入与平台面单，参考价 ¥0–200，3.5 元起寄件）；service_id=50 是上海中通吉的（中通；官方 3 元寄件；手机端 2 步打抖音单；无电子面单账号也可发货；快递员上门；无法打印时快递员代打）——不要混淆。参考价：快递助手 ¥0–729、我打打单 ¥0–998、灵通打单 ¥0–218、发货易 ¥0–358、中通吉快递管家 ¥0–180，均有 7 天试用、PC + 移动端。

### 15.3 抖店开放平台 API（开发者认证后；一期不采用）
- 订单：`/order/searchList`、`/order/orderDetail`、`/order/addOrderRemark`、`/order/batchDecrypt`（收费）；发货：`/order/logisticsAdd`（整单，2000/s）、`logisticsEdit`、`logisticsAddMultiPack`、`logisticsAddSinglePack`、`queryOrderLogistics`、`queryLogisticsCompanyList`、预发货两个；电子面单：`/logistics/newCreateOrder`（`sender_info` 必须与 `listShopNetsite` 返回一致、`receiver_info` 必填且支持密文、`sender_fetch_time` 语义不明、`ebill_delivery_info` 仅在线寄件场景）、`updateOrder`（有虚拟号能力）、`cancelOrder`、`getOutRange`、`fetchBluetoothCmd`（仅顺丰、中通、圆通、极兔、韵达、邮政、申通，**不含京东**）、`listShopNetsite`、`getRecommendedAndDeliveryExpressByOrder`、`trackNoRouteDetail` 等；地址：`/address/create`、`/address/list`。
- **没有**在线寄件下单接口。
- 权限：自用型 "商家后台系统" 类目默认 API 权限包**包含**抖音电子面单、物流发货、订单信息查询、运单轨迹、商家地址列表、解密/脱敏等（《应用类目权限指引》，官方）。
- **开发者资质（11-17 官方）**：注册开发者 → 申请类目资质（系统功能说明书、国家软著证书、绑定店铺；1–3 工作日）→ 新建应用（1 个）→ 店铺授权 → `/token/create`（`authorization_self`，7 天有效，可刷新）→ 调用 `openapi-fxg.jinritemai.com`。**软著主体、开发者主体、店铺主体三者一致**；还要研发支出证明、登录与功能截图；入驻标准写"企业"，FAQ 写"只支持公司主体"，**个体工商户是否算企业未明确，需工单确认**。11-14 控制台现状：开发者认证未认证、接口费用账户未开通、已建应用 0。
- 蓝牙打印机：抖店 App 支持列表（图片，含快麦 KM-202MB 等）。

### 15.4 厂商代发（11-17 判不可行）
厂家须是已入驻抖店的主体，个人不能开通；一个店铺只能是一种身份；订单按商品维度分配给已绑定厂家；厂家需自己开电子面单、用服务市场工具或 API 发货，**看不到明文地址**；供应商原因的赔付由供应商承担。→ 对分散个人织女基本不可行。

### 15.5 订单导出（11-17）
订单报表字段：主订单编号、子订单编号、选购商品、商品规格、数量、商品ID、**商家编码**（适用报表类型待实测）；导出文件**加密，解压密码发到验证手机/邮箱**；收件人为密文；上限 100 万条。

### 15.6 虚假交易（11-18）
《【虚假交易】处置细则》（2026/08/09 更新）：虚构交易获取虚假销量等即违规；处置含取消数据、限制营销、违约金（AI 摘要：支付金额 1%，最低 1000 元，最高 20000）、店铺清退。→ **自己小号下单或织女下单后退款不可用**。

✅ 当前有效：一期使用在线寄件 + 订单 CSV；开放平台 API 作为后续备选；不做厂商代发；不自买订单。

### 20.2 云数据库集合（13 核心 + 2 占位；11-22 更新）
`users`（`roles[]`、`tags[]`、`weaverNo`、`status`、`acceptingOrders`、`acceptsTrial`、`restDays`、`dailyCapacityMin`、`extraColors[]`、`doudianAddressAlias/Text`、`screeningStage`、`creatorLevel`）、`styles`（`skuCode`、`riskClass`、`standardMin`、`requiredColors[]`、`patternId`、`craftFeeFen`、`royaltyFen`、`yarnPoolAccrualFen`、`shippingShareFen` 等）、`patterns`（结构化步骤 JSON：部位 → 圈/行）、`yarnCatalog`、`orderPackages`（`dispatchableAt`、`bagQrCode`、`channel=douyin_online` 等）、`externalOrderIndex`、`dispatchOffers`、`photoReviews`、`shipments`、`yarnClaims`、`ledger`、**`weaverStock`（余货）**、**`bagStickers`（袋码贴纸）**；二期占位：`addresses`、`sampleShipments`；另 `settlementBatches`、`auditLog`、`rateLimit`、`config`。

### 20.3 订单包状态机与账本
- `confirming`（派单前合单窗口）→ `waiting_dispatch` → `offered`（1 小时确认）→ `making` → `photo_review` → `awaiting_seal` → `ready_to_ship`（期望取件时段仅作提示）→ `shipped` → `signed`（7 天检视）→ `settled_ready`；异常：`manual_hold`、`cancelled_full`、**`cancelled_made`（开工后取消）**、`returned`。
- 账本确定性键：`craft:`、`ship_reimb:`、`trial_comp:`（二期）、`yarn_in:`、`yarn_out:`、`royalty:`、`payout:`；个人线材池不可透支校验（先写占坑 → 聚合余额 → 严格校验 → 写负流水）。

### 20.4 抖店 CSV 增量导入规范
前端读 ArrayBuffer，先 `utf-8` fatal，失败降级 `gb18030`，去 BOM；PapaParse 按中文表头解析；拦截科学计数法订单号和未知 `skuCode`；先 `previewDoudianCsv` Dry-Run；按 `externalOrderIndex` 去重；新单按 `sha256(省|市|脱敏姓名|脱敏手机)` 合单；状态回导（接单前整包退款 → `cancelled_full`；接单后 → `cancelled_made`；出现单号 → `shipped`；出现签收时间 → `signed` 且 `settleEligibleAt = signedAt + 7d`）；每日 8:30 重导。

### 20.5 三期路线与一期冻结范围
一期 MVP：独立新仓 + 3–5 位种子织女（**仅固定款**）+ 抖店 CSV 导单与在线寄件 + 12 基础色与个人不可透支补色池 + 内部录图解与歌词式图解 + 八边封袋贴纸 + 运营审照 + 14 天手工结款。**一期明确不做**：买家小程序商城与微信支付、抖店/快递 API、外部创作者注册、安卓悬浮窗 APK、自动银行打款与退货再售池。二期：买家自主下单测新款、快递100 双通道（含样品线下支付）、外部创作者按件分成、四轮漏斗与志愿评委、退货验封签再售（专用退货地址）、批量结款、非固定款与兜底。三期：精品/标准分档、小团队与商家批量单、模块化图解、博主教学与代钩分佣、安卓悬浮窗 APK；待评估：小程序打赏、图解订阅或买断（需微信支付，一期不做）。

### 20.6 一期开工前的 4 道闸门与待拍板清单
- **闸门**：①法务税务定性；②抖店后台两项实测（导出真实订单 CSV 核对字段；**用第一批真实订单**验证异地织女的在线寄件）；③首批业务参数（种子织女名单、1–3 款标准工时、12 基础色号与条码表、每单费用拆分、线材池每单划入金额；二期参数：成团数 N、风险溢价、补偿封顶、样品运费补贴、贴纸低库存阈值）；④独立环境（独立 AppID、独立云环境、抽骨架建仓、抖店地址库录织女地址、设置专用退货地址）。
- **一期闭环 5 段流程推敲**（当前断点：第 1 段）：①开播前准备——第一批主推款是否严格只用 12 基础色（推荐是）；线团条码被撕掉时是否"扫码为主 + 合照兜底"（推荐是）；八边封袋"二维码贴纸"与"一次性封签"分开两张（推荐分开）；种子织女是否挑 1 位异地织女用真实订单跑通在线寄件；②成交与导单（CSV 频次、库存与工时联动、8:30 重导、余货与优先派单）；③派单与制作（派单超时与卡单 SOP、歌词式图解异常反馈）；④质检与发货（驳回重拍时限、取件时段仅作提示、贴纸损坏换码、快递员爽约重约）；⑤签收与结款（签收 CSV 回导周期、封签损坏纠纷、14 天手工转账与线材池对账）。
