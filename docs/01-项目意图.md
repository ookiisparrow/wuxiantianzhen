# 01 项目意图

> 立项日期：2026-11-22　　来源：`docs/reference/全部资料汇总.md`（含全部历史）、`archive/2026-11-22-pre-project/`（原始文件）
> 本文只写"为什么做、做给谁、做什么不做什么"。怎么做见 `03-项目设计.md`，证据见 `02-调研记录.md`，谁在何时定了什么见 `04-决策日志.md`。

## 1. 一句话

**「无限天真」：一个去中心化的云端手工艺工厂。** 把分散在各地的钩织手艺人（织女）的产能，通过直播间销售的稳定爆款订单组织起来，由织女在自己家中制作并直接寄给买家；平台不赚织女的手作利润，靠直播间日常消耗品带货、教程与图解、B 端服务费维持运营。品牌理念：想让世界好一点点。

## 2. 要解决的问题

| 问题 | 现状 | 本项目的做法 |
|---|---|---|
| 织女有手艺没订单 | 散在各地，零散接单，收入不稳 | 用直播间订单给她们稳定的、按件计价的工作 |
| 手作交付不稳定 | 同款不同人做出来不一样，退货率高 | 标准图解、统一材料（12 基础色）、拍照审核、封签 |
| 平台要的是"规模"，手作是"个人" | 集中仓库成本高、管理重 | 不囤货、不集中仓，织女直发；平台只做分发、质检、结算 |
| 手作成本不可回收 | 买家取消、退款，织女白做 | 派单前缓冲、固定款复用、非固定款隔离风险 |
| 对外说"不赚利润" | 必须可核验，不能随意混入成本 | 费用构成可公布，运营费单独记账 |

## 3. 做给谁

- **织女**（制作者）：手机不离手、习惯微信，看图解比看文字快，最怕"白做"和"算不清钱"。她们**看不到买家信息**，所有问题找平台客服。
- **买家**（一期在抖音直播间下单，二期老玩家在小程序测新款）。
- **运营**（创始人本人 + 少量人手）：每天导订单、派单后处理异常、批量发货、结款。
- **创作者**（二期起）：设计形象与图解，按件固定金额分成。
- **志愿评委**（二期起）：作品筛选与寄出前审照。
- **B 端**（三期）：博主、达人、商家，使用云端织女产能。

## 4. 商业模式

1. **直播间日常消耗品带货（主收入）。**
2. 精品教程与配套内容（图解创作、成品拍摄、博主教学视频）。
3. 付费图解制作服务（不会写图解的创作者可付费制作，图解可对外收费）。
4. 第三方 B 端与达人服务费（含帮爆火视频博主承接代钩订单并分账）。

**钩织业务微利自养（11-22 第 2 轮）**：费用构成里公开一项"平台服务费"，只覆盖运营成本、不追求利润；对外只说能用账目证明的话（公布每单费用构成，含平台服务费），避免"公益""慈善"字样。不再使用"钩织完全不赚钱、由直播间其他商品覆盖"的绝对说法。

## 5. 产品与渠道原则

- **品类**：无实际功能的摆件与挂件，做 IP 化、形象化、系列化（如「天真宝宝」sasa/papa/haha，及梦想厨房、奇幻森林、旅行家、小花园）；避开服装与实用类（尺码、高退换）。
- **直播间只主推个位数稳定款，甚至持续单款打爆**：压缩织女备料与学习成本、降低同行抄款价值、便于控制风险。
- **一期**：交易全部在抖店完成，不做买家小程序与微信支付。
- **二期**：微信小程序开放买家自主下单，承接老玩家测新款；稳定后再推上直播间。

## 6. 核心业务原则（贯穿全部设计）

1. **织女直发**：货从织女家直接寄给买家，不回仓；织女与买家全程信息隔离。
2. **规则优先于人工**：能用规则解决的不靠人判断；人工只处理异常。
3. **结果导向**：只记关键节点和结果，不要求织女汇报过程；流程单向线性，前一步完成才开下一步。
4. **平台中立，偏向保护织女**：规则上织女是弱者，可容忍对织女有利的小漏洞。
5. **零垫资、零坏账**：线材采用个人预算池，不允许透支；不向织女收押金式资金（保证金**再考量**）。
6. **先留接缝再开发**：一期只做最薄闭环，二三期只保留数据字段与边界，不提前写二三期代码。
7. **账是唯一事实**：金额用整数分；所有资金变动写不可变流水，余额由流水汇总；纠错用冲正。
8. **隔离风险**：固定款与非固定款分开设计；不愿承担风险的织女看不到非固定款。
9. **不碰灰色**：不自买刷单、不绕平台规则、不把买家明文落库。

## 7. 范围（2026-11-22 第 3 轮重定）

> 取代原"一/二/三期"。依据：用户确认两池结构、12 个月内 500+ 织女、首个可规模化版本 6 个月内上线、小程序池与直播池同期上线。

### 阶段 0：履约质量验证（立即开始，与阶段 1 并行）
3–5 位熟人织女，只做固定款；抖店订单用 CSV 导出 + ERP 或手工在线寄件；运营审照；手工结款。目的是验证"图解 → 制作 → 审照 → 封签 → 寄件"的质量链，规则沿用到规模版。**不作架构。**

### 阶段 1：首个可规模化版本（目标 6 个月内）
- **直播池**（≤500 位）：抖店订单自动进入；验证期用 ERP，同时立即启动软著与开发者资质，就绪后切抖店开放平台 API（订单 API + 电子面单 API）。
- **小程序池**（无上限）：买家小程序下单 + 微信支付；自营加受托加工，平台是卖方；快递100 上门取件（线上预充，平台付运费）；订单来源以老玩家与社群为主。
- **共同能力**：自动派单；分级实名（接单前验手机号与微信，首次结款前实名，月收入达税务门槛时完整认证）；付款通道可切换，二期前评估灵活用工；信用分抽检 + 运营复核，**同步实现志愿者审核功能**；线材少数主供应商深度合作；客服：买家走抖店客服，织女走小程序内工单与社群，异常规则自动改派；直播池席位按"表现动态排名 + 城市配额"混合进出。
- **明确不做**：外部创作者注册（一期只做平台自有形象）；安卓悬浮窗 APK；平台自有品牌线材；区域集货与质检点（只留字段）；团队账号（只留字段）；非固定款及其兜底（待定）；打赏、订阅、买断。

### 阶段 2：放大
外部创作者按件分成；织女与小团队（`orgId`）；平台品牌线材与更多供应商；灵活用工付款；区域点（视质量与物流情况）；非固定款；B 端与博主代钩单。

### 待评估
小程序打赏、图解订阅或买断（需微信支付，类目与税务待核实）。

## 9. 成功的样子（11-22 第 1 轮：用户接受以下 5 条，不设数量门槛，由用户主观判断何时进入二期）

> 口径由我根据业务意图整理，已被用户确认。

- 3–5 位种子织女跑通 1–2 个固定款的完整链路：导单 → 派单 → 制作 → 审照 → 装袋封签 → 在线寄件 → 签收 → 7 天 → 14 天结款。
- 任意一单的"订单号 ↔ 织女 ↔ 袋码 ↔ 运单号"可在后台一分钟内查清。
- 运营每日手工步骤（导出 CSV、8:30 重导、批量在线寄件、回导）在 1 小时内完成。
- 账本余额与流水逐笔对得上；织女自己能看懂每一笔钱。
- 没有一次买家明文地址落库或被织女看到。

## 10. 长期方向与结构预留（2026-11-22 第 2 轮确认）

用户在第 2 轮对 12 个结构性问题的回答，决定了"一期怎么做、哪些接缝现在就留"：

| 方向 | 决定 |
|---|---|
| 规模目标 | **两池结构（用户 11-22 澄清）**：**直播池**——直播间订单只需要约 500 位织女供给；**小程序池**——500 之外新增的织女不接直播间订单，只在微信小程序上处理订单，人数无上限。要快速实现。一期 3–5 位织女的手工链条只作验证，不作架构。 |
| 定位 | 钩织业务微利自养，公开"平台服务费" |
| 主体 | 一期个体户；二期前评估另设公司；AppID 注册时选能长期使用的主体 |
| 织女关系与付款 | 一期承揽加工费 + 手工转账；付款做成可切换通道，二期前再决定是否切到灵活用工或代发平台 |
| 知识产权 | 一期只做平台自有形象；现在先做自有形象著作权登记与商标检索；外部创作者二期再谈 |
| 履约 | 直发为主；预留经由区域点的可空字段（`hubId`），功能不做 |
| 线材 | 指定供应商直发给织女，平台从线材池结算；一期由运营手工代下单 |
| 多款订单 | 整包一位织女；常买组合做成独立套装款号 |
| 质检 | 一期逐单审；审照做成可按规则跳过的节点，稳定后按信用分抽检 |

| 后端 | 一期微信云开发；买家信息处理收口在一个模块；三期若需解密再拆出"抖店网关" |
